# Deletion resource registry

Current source: 6267a299206a4e9e48ca987891e7c971567c1223, 2026-10-19. This supersedes the historical 43-resource inventory. Fresh Staging and Production schema snapshots, including columns and foreign keys, are in evidence/20261019-*-schema.json. Source classifications are in evidence/certified-resource-classifications.json. The census is complete for public/private/Auth/Storage catalogs; processor log/backup retention and native-device erasure still have the limitations in cross-platform-test-matrix.md and legal-handoff.md.

The registry contains 50 exact account-owned tables. The worker never treats an unknown public/private table, foreign table, partitioned table or materialized view as deletable. Unknown resources identify only their schema/table names in a fail-closed error. Adding account ownership to an explicitly global table also requires reclassification.

Cleanup order: revoke provider grants while credentials exist; remove exclusive account leaves; preserve or escalate ambiguous/shared records; erase exclusively owned households only after locking and checking all household-linked ownership, including private Premium receipts; remove remaining credentials/profile; hard-delete Auth; independently recount all owned tables, private AI metadata, provider references, Storage and Auth subresources; then produce the five-field proof. The deletion action of an account-private receipt does not remove its value as evidence that another adult owns data in a household.

Every mutation is fenced by request/fence/lease/control and the original 30-day recovery cutoff. Eight attempts with bounded backoff end in visible operator action. Shared cases retain a seven-day target. No automatic ownership transfer, another-adult deletion, or unresolved terminal success is permitted.
