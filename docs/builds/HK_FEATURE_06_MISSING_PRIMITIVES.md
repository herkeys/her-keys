# HK-FEATURE-06 — Missing primitives register and integration candidates

Everything Home OS would like from the common foundation that `14bd58e` does not provide. **Discovery is authorized; autonomous schema or product-semantic creation is not.** Nothing here was built as a durable semantic. Each row says whether a feature-local solution exists, whether the capability would be a NEW durable semantic, and whether an owner checkpoint is required before anything is built.

Baseline: `repair/hk-integration-readiness-01` @ `14bd58e`. Register opened at HM1; rows are added as later phases find them.

## 2. Integration candidates

None of these is implemented here. Home does not build sibling domains.

| ID | Candidate |
|---|---|
| `HK-INT-WAVE2-LIFE-REGISTRATION` | Reconcile the Life landing surface after F05 / F06 / F08 exist: replace hand-edits of `app/(app)/life/index.tsx` and `_layout.tsx` with one registration mechanism. Home currently uses `/life/home` and touches neither. Also reconcile the hub's Home row copy (`describeHome`: "N systems running" asserts operation; "0 systems running" for an empty household). |
| `HK-INT-HOME-TODAY-01` | Home attention → Today briefing. Today and Home must show the same judgment for the same canonical facts; Home uses `attentionFor` and factual conditions only. |
| `HK-INT-HOME-CALENDAR-01` | Home service visits → Calendar. A visit is a canonical commitment (`CalendarEvent`); Home creates it in the Home category and never schedules or optimizes. MP-06-08 (visit outcome). |
| `HK-INT-HOME-SYSTEMS-01` | Repeatable Home operations → Systems: a Home task that repeats is a candidate for a System **only when the user chooses**; needs an approved System-creation path (MP-06-04) and F04's run semantics (MP-06-03). |
| `HK-INT-HOME-PEOPLE-01` | Home responsibility → People OS: generalized delegation, person creation (MP-06-05), provider identity (MP-06-10). |
| `HK-INT-HOME-MONEY-01` | Repair / maintenance financial context → Money OS (MP-06-13). |
| `HK-INT-HOME-LIFEADMIN-01` | Warranty / manual / document relationships → Life Admin. Home shows an operational admin requirement as a task; no vault. |
| `HK-INT-TIO-HOME-01` | Talk It Out → a reviewed Home proposal (the `categoryHint: 'home'` role already exists on an interpretation). |
| `HK-INT-HOME-PATTERN-01` | Completion / observation history → future repeated-friction and pattern intelligence. Home preserves the evidence (append-only `completed` / `reopened` / `skipped` observations) and builds none of it. |
| `HK-INT-HOME-REOPEN-01` | One shared reopen/retract semantic (MP-06-01) so every feature agrees what a `reopened` observation means. |
